### Система массового обслуживания M/M/* с усложнениями

Агентное моделирование на основе дискретно-событийного подхода.

**Предметная область:** кофейня. Клиенты приходят за кофе, их обслуживают несколько бариста.

**Задание:**
- реализовать систему M/M/* с двумя дополнительными правилами (ООП);
- построить приложение на основе агентного моделирования с дискретно-событийным подходом;
- использовать визуализацию процессов (таймер);
- вычислить эмпирические распределения числа занятых операторов, числа клиентов в очереди и времени пребывания клиента в очереди;
- построить полигоны и гистограмму частот, сделать выводы о параметрах функционирования системы.

## Реализация

### Базовая модель и два дополнительных правила

Базовая система — **M/M/N**: простейший входящий поток, экспоненциальное обслуживание, N обслуживающих приборов.

К ней добавлены два правила:

| Правило | Что означает |
|---|---|
| **1. Ограниченная очередь** | Мест в очереди конечное число. Клиент, не нашедший свободного места, разворачивается и уходит — это **отказ** |
| **2. Нетерпеливость заявок** | У каждого клиента свой запас терпения. Если очередь не дошла до него за это время, он уходит, не купив кофе |

Параметры модели:

| Параметр | Значение | Роль |
|---|---|---|
| `λ` | 1.2 чел/мин | Интенсивность прихода клиентов |
| `μ` | 0.5 чел/мин | Интенсивность обслуживания одним бариста (2 минуты на кофе) |
| `N` | 3 | Число бариста |
| Мест в очереди | 5 | Ограничение по правилу 1 |
| Среднее терпение | 5 мин | Параметр правила 2 |
| Прогрев | 200 мин | Отбрасывается, чтобы убрать переходный режим |

### Агентный подход

Агенты трёх типов, у каждого свои характеристики и своё правило поведения. Все они наследуют общий интерфейс из двух методов:

```python
class Agent:
    def get_next_event(self):
        """Когда агенту нужно что-то сделать."""
        return INF

    def process_event(self):
        """Агент делает то, что нужно."""
        pass
```

| Агент | `get_next_event()` возвращает | Что делает в `process_event()` |
|---|---|---|
| **Дверь** | Момент прихода следующего клиента | Впускает клиента и планирует следующий приход |
| **Бариста** | Момент окончания обслуживания (∞, если свободен) | Отпускает клиента и берёт первого из очереди |
| **Клиент** | Момент, когда кончится его терпение | Уходит из очереди, не дождавшись |

Клиент в очереди — **отдельный автономный агент**. Именно поэтому правило нетерпеливости реализуется естественно: клиент сам решает, когда ему надоест ждать, среде не нужно за ним следить.

```python
class Client(Agent):
    def __init__(self, cafe, arrival_time):
        self.arrival_time = arrival_time
        self.patience_end = arrival_time + exp_rv(1.0 / cafe.patience)

    def get_next_event(self):
        return self.patience_end

    def process_event(self):
        self.cafe.client_gave_up(self)
```

Кофейня `Cafe` — это **среда**, в которой живут агенты. Она хранит очередь, список бариста и статистику, а агенты обращаются к ней за действиями.

### Алгоритм моделирования

```python
def step(self):
    best_time = INF
    best_agent = None
    for agent in self.all_agents():
        ti = agent.get_next_event()
        if ti < best_time:
            best_time = ti
            best_agent = agent

    self.accumulate(best_time - self.t)   # копим статистику за прошедшее время
    self.t = best_time
    best_agent.process_event()
```

Список агентов пересобирается на каждом шаге, потому что клиенты в очереди появляются и исчезают:

```python
def all_agents(self):
    return [self.door] + self.baristas + self.queue
```

Модельное время прыгает сразу к ближайшему событию — между событиями в кофейне ничего не происходит.

### Три варианта развития событий при приходе клиента

```python
def client_arrived(self):
    self.came = self.came + 1
    barista = self.free_barista()

    if barista is not None:
        # есть свободный бариста - обслуживаем сразу, ждать не пришлось
        barista.start_service(Client(self, self.t))
        self.record_wait(0.0)

    elif len(self.queue) < self.places:
        # ПРАВИЛО 1: место в очереди есть - встаём
        self.queue.append(Client(self, self.t))

    else:
        # ПРАВИЛО 1: мест нет - разворачиваемся и уходим (отказ)
        self.refused = self.refused + 1
```

### Сбор статистики

Число занятых бариста и длина очереди живут во времени, поэтому их распределения считаются **по доле времени**, а не по числу событий:

```python
def accumulate(self, dt):
    if self.t < self.warmup:
        return
    busy = self.busy_count()
    qlen = len(self.queue)
    self.time_busy[busy] = self.time_busy.get(busy, 0.0) + dt
    self.time_queue[qlen] = self.time_queue.get(qlen, 0.0) + dt
    self.stat_time = self.stat_time + dt
```

Время пребывания в очереди записывается по каждому клиенту, вошедшему в кофейню: ноль для тех, кто попал к свободному бариста, фактическое ожидание для дождавшихся и время до ухода для нетерпеливых.

## Теоретические значения

Система с обоими правилами — это **процесс гибели и размножения** с состояниями от 0 до `N + мест`:

```python
def theory_probs(lam, mu, servers, places, patience):
    nu = 1.0 / patience
    top = servers + places
    p = [1.0]
    for n in range(1, top + 1):
        out_rate = min(n, servers) * mu + max(n - servers, 0) * nu
        p.append(p[n - 1] * lam / out_rate)
    total = sum(p)
    return [v / total for v in p]
```

## Вывод

Реализована агентная модель кофейни на основе дискретно-событийного подхода:

- три типа агентов с общим интерфейсом `GetNextEvent` / `ProcessEvent`, каждый со своими характеристиками и своим правилом поведения;
- к базовой M/M/3 добавлены ограниченная очередь и нетерпеливость клиентов;
- эмпирические распределения числа занятых бариста, длины очереди и времени ожидания совпали с теоретическим расчётом через процесс гибели и размножения, ошибка по всем шести показателям не превысила 0.007.

**Выводы по работе кофейни при заданных параметрах.**

Одновременно 8 % времени кофейня простаивает полностью — все три бариста свободны. Получается парадокс: система одновременно и недогружена в среднем, и теряет каждого девятого клиента. Причина в **случайности потока**: клиенты приходят не равномерно, а пачками, и как раз в эти моменты очередь и переполняется.

Сравнение сценариев (теоретический расчёт, его легко проверить в программе):
