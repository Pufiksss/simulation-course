### Система массового обслуживания M/M/1

Моделирование простейшей системы M/M/1.

**Предметная область:** пункт выдачи заказов (ПВЗ) с одним оператором.
Событие — приход клиента за посылкой и окончание её выдачи.

**Задание:**
- спроектировать и реализовать приложение моделирования на основе дискретно-событийного подхода;
- вычислить эмпирические распределения числа клиентов в системе и времени пребывания клиента в очереди;
- построить полигон и гистограмму частот;
- сделать выводы относительно параметров функционирования системы.

---

## Реализация — дискретно-событийный подход

Главная идея дискретно-событийного моделирования: между событиями в системе **ничего не меняется**, поэтому нет смысла двигать время маленькими шагами. Модельное время прыгает сразу к ближайшему событию:

Событий в модели два: **приход клиента** и **окончание обслуживания**.

Параметры модели:

| Параметр | Значение | Роль |
|---|---|---|
| `λ` | 0.8 чел/мин | Интенсивность прихода клиентов |
| `μ` | 1.0 чел/мин | Интенсивность обслуживания одним оператором |
| `ρ = λ/μ` | 0.8 | Коэффициент загрузки оператора |
| Время моделирования | 100 000 мин | Длительность прогона |
| Прогрев | 1 000 мин | Отбрасывается, чтобы убрать переходный режим |

### Переменные состояния

Минимальный набор, из которого выводится всё остальное:

| Переменная | Смысл |
|---|---|
| `t` | Модельное время |
| `x` | Число клиентов на обслуживании (0 или 1, оператор один) |
| `y` | Число клиентов в очереди |
| `queue` | Моменты прихода тех, кто стоит в очереди — нужны для расчёта времени ожидания |

Число клиентов в системе `x + y` отдельно не хранится: оно вычисляется в любой момент.

### Алгоритм моделирования

   
```python
while t < sim_time:
    tau = exp_rv(lam)
    if x > 0:
        delta = exp_rv(mu * x)
    else:
        delta = INF

    if tau < delta:
        t = t + tau
        if x < 1:
            x = x + 1
            serving_arrival = t
            waits.append(0.0)          # ждать не пришлось
        else:
            y = y + 1
            queue.append(t)
    else:
        t = t + delta
        systems.append(t - serving_arrival)
        if y == 0:
            x = x - 1
            serving_arrival = None
        else:
            y = y - 1
            arrived = queue.pop(0)
            waits.append(t - arrived)  # сколько этот клиент простоял
            serving_arrival = arrived
```


Оба времени разыгрываются одинаково, методом обратной функции:

```python
def exp_rv(rate):
    return -math.log(base_random()) / rate
```

### Сбор статистики

**Число клиентов в системе** — величина, живущая во времени, поэтому её распределение считается **по доле времени**, а не по числу событий:

```python
def state_distribution(time_in_state, total_time):
    top = max(time_in_state.keys())
    return [time_in_state.get(n, 0.0) / total_time for n in range(top + 1)]
```

**Время ожидания в очереди** считается по каждому клиенту отдельно. Момент прихода запоминается в списке `queue`, а в момент, когда клиента берут на обслуживание, разность даёт время ожидания. Тем, кто попал к свободному оператору сразу, записывается ноль.


Условие существования стационарного режима — `ρ < 1`. Если `λ ≥ μ`, клиенты приходят быстрее, чем оператор успевает их обслуживать, очередь растёт неограниченно, и теоретические формулы теряют смысл. Программа проверяет это условие и не даёт запустить такую модель.

## Результаты (λ = 0.8, μ = 1.0, 100 000 минут, обслужено 79 434 клиента)

| Показатель | Эмпирика | Теория | Ошибка |
|---|---|---|---|
| Коэффициент загрузки оператора | 0.7999 | 0.8000 | 0.0001 |
| Среднее число клиентов в системе | 3.9917 | 4.0000 | 0.0083 |
| Средняя длина очереди | 3.1917 | 3.2000 | 0.0083 |
| Среднее время ожидания, мин | 3.9779 | 4.0000 | 0.0221 |
| Среднее время в системе, мин | 4.9748 | 5.0000 | 0.0252 |
| Вероятность ожидания > 10 мин | 0.1083 | 0.1083 | 0.0001 |

- максимум клиентов в системе за прогон — **32**;
- максимальное ожидание — **43.1 мин** при среднем 4;
- более 5 клиентов в системе — **26.4 %** времени.

**Полигон частот** числа клиентов в системе лёг на теоретическую геометрическую зависимость `P{n} = 0.2 · 0.8^n` по всему диапазону.


## Вывод

Реализовано дискретно-событийное моделирование пункта выдачи заказов как системы M/M/1:

- модельное время прыгает от события к событию, на каждом шаге разыгрываются два конкурирующих времени (приход клиента и окончание обслуживания), побеждает ближайшее;
- благодаря отсутствию последействия у экспоненциального распределения оба времени можно разыгрывать заново на каждом шаге, не храня недоигранные остатки;
- эмпирическое распределение числа клиентов в системе совпало с теоретическим `P{n} = (1 − ρ)ρ^n`;
- все шесть показателей функционирования совпали с теоретическими формулами M/M/1 с ошибкой не более 0.03.
